# Docs

A change in behavior updates its `docs/<feature>.md`. A new feature gets a new `docs/<feature>.md` that starts with its title, a blank line, then a sentence saying what the feature is and where it lives (`pnpm check docs` fails without it). No list names the docs, so nothing else changes. A doc that many pull requests edit is split into a folder with one file per part, as `docs/trip-lines/` is, with `docs/<feature>.md` kept as its short index; `pnpm check doc-links` fails on a link to a file or heading that isn't there. Only touch the README itself for setup, commands or deployment. Docs explain backend ideas with a short "> **Frontend analogy:**" note, since the owner is a frontend engineer.
